0.1 Usuario de Ejecución

📍 Todo el manual se ejecuta como python (grupo wheel), usando sudo en comandos privilegiados. No se usa root directamente. Conexión: SSH con su usuario institucional → sudo su - python → verificar con whoami. Si el usuario no existe o no tiene sudo, ejecutar primero el Manual de Infraestructura (sección III).

I. Prerrequisitos del Sistema

1.1 Sincronizar reloj del sistema

⏭️ Verificación previa. Si chronyc tracking ya devuelve Leap status: Normal, salte a la sección 1.2.
sudo chronyc -a makestep # Debe aparecer 200 OK # Si aparece "506 Cannot talk to daemon": sudo dnf install -y chrony sudo systemctl enable --now chronyd sudo chronyc -a makestep chronyc tracking # Verificar "Leap status: Normal"

1.2 Instalar dependencias de desarrollo para RHEL 10

⏭️ Verificación previa. Si rpm -q gcc openssl-devel libffi-devel zlib-devel los devuelve todos instalados, salte a la sección II (o a la III si no hay instalaciones previas que limpiar).
⚠️ RHEL 10 / dnf5. El subcomando groupinstall está deprecado. Use dnf group install (con espacio) o dnf install @"Development Tools".
sudo dnf group install "Development Tools" -y sudo dnf install -y openssl-devel bzip2-devel libffi-devel zlib-devel \ xz-devel readline-devel sqlite-devel tk-devel ncurses-devel \ libuuid-devel wget make gcc gcc-c++ libxcrypt-compat
En producción (sin internet) estos dnf install funcionan contra los repos RHEL suscritos.

II. Limpieza de Instalaciones Previas

⏭️ Solo si aplica. Ejecute esta sección únicamente si existen instalaciones residuales de Python 3.13 (por ejemplo, una compilación previa fallida). Si es una instalación limpia, salte a la sección III.
# Detener procesos en ejecución sudo pkill -f "python3.13" 2>/dev/null || true # Eliminar binarios y alias sudo rm -f /usr/local/bin/python3.13 /usr/local/bin/python3.13-config sudo rm -f /usr/local/bin/pip3.13 /usr/local/bin/python3-app sudo rm -f /usr/local/bin/pip3-app /usr/local/bin/idle3.13 sudo rm -f /usr/local/bin/2to3-3.13 /usr/local/bin/pydoc3.13 # Eliminar instalación y librerías sudo rm -rf /usr/local/python3.13 /usr/local/lib/python3.13 sudo rm -f /usr/local/lib/libpython3.13* # Eliminar registro del linker sudo rm -f /etc/ld.so.conf.d/python313.conf sudo ldconfig # Eliminar fuentes previas sudo rm -rf /usr/src/Python-3.13.5 /usr/src/Python-3.13.5.tgz

III. Descarga y Compilación de Python 3.13.5

3.1 Preparar directorio de compilación

cd /usr/src sudo rm -rf Python-3.13.5

3.2 Descargar fuente oficial

sudo wget https://www.python.org/ftp/python/3.13.5/Python-3.13.5.tgz sudo tar xzf Python-3.13.5.tgz cd Python-3.13.5
📍 Ambiente Producción (OFFLINE): si el servidor no tiene acceso al puerto 443, copie previamente Python-3.13.5.tgz desde la carpeta compartida institucional o vía SCP a /usr/src, y continúe con sudo tar xzf Python-3.13.5.tgz.

3.3 Configurar con parámetros CRÍTICOS para el proyecto

cd Python-3.13.5/ sudo ./configure --prefix=/usr/local/python3.13 \ --enable-shared \ --enable-optimizations \ --with-computed-gotos \ --with-openssl=/usr \ --with-openssl-rpath=auto \ LDFLAGS="-Wl,-rpath /usr/local/python3.13/lib"

Parámetros obligatorios:

  • --enable-shared → genera libpython3.13.so (Py_ENABLE_SHARED=1), requerido por PyInstaller y Spark.
  • --with-openssl-rpath=auto → evita errores de libssl en runtime.
  • LDFLAGS → asegura que el linker encuentre las librerías compartidas.

3.4 Compilar e instalar

# Compilar usando todos los núcleos sudo make -j $(nproc) # Instalar sin sobrescribir el Python del sistema (RHEL trae 3.12) sudo make altinstall

Esto instala python3.13 y pip3.13 sin reemplazar /usr/bin/python3.

IV. Configuración de Librerías Compartidas

⏭️ Verificación previa. Si ldconfig -p | grep libpython3.13 ya lista la librería, salte a la sección V.

4.1 Registrar ruta de librerías en el linker

echo "/usr/local/python3.13/lib" | sudo tee /etc/ld.so.conf.d/python313.conf sudo ldconfig

4.2 Corregir compatibilidad libffi para RHEL 10

📍 Pegado directo en consola. El fragmento usa if/then de Bash (no local, que solo es válido dentro de funciones). Cópielo tal cual en la terminal logueada como python.
if [[ ! -f /usr/lib64/libffi.so.6 ]]; then libffi=$(find /usr/lib64 -name "libffi.so.*" | head -1) if [[ -n "$libffi" ]]; then sudo ln -sf "$libffi" /usr/lib64/libffi.so.6 sudo ldconfig fi fi

VI. Configuración de Accesos Globales

⏭️ Verificación previa. Si python3-app --version ya devuelve Python 3.13.5, salte a la sección VII.

6.1 Crear alias oficiales del proyecto

6.2 Verificar que los alias apuntan correctamente

python3-app --version # Debe mostrar: Python 3.13.5 which python3-app # Debe mostrar: /usr/local/bin/python3-app

VII. Prueba de Librerías Base (dentro del venv, offline)

📍 Las pruebas con librerías se hacen DENTRO del entorno virtual del proyecto, nunca en el Python global. Así no se contamina la instalación base y se replica el entorno real del ETL. En producción (sin internet) las librerías se instalan offline desde /opt/librerias.
⏭️ Prueba opcional. Esta sección solo confirma que el Python compilado funciona con librerías nativas dentro del venv. Si ya validó la sección V, puede omitirla y pasar al Manual 3.

Paso 1 — Ir al proyecto y activar el venv

# Crear el proyecto si no existe (usuario python, grupo python) mkdir -p /home/python/sri_datos_abiertos_facturacion cd /home/python/sri_datos_abiertos_facturacion pwd # Confirmar la ruta # Si el venv no existe aún, créelo con el Python 3.13.5 recién instalado: # /usr/local/python3.13/bin/python3.13 -m venv venv source venv/bin/activate which python # Debe apuntar a .../venv/bin/python

Paso 2a — Con internet (Desarrollo)

pip install pandas numpy

Paso 2b — Sin internet (Test/Producción): instalar offline desde /opt/librerias

# En una máquina con internet, descargar los wheels: # pip download pandas numpy --python-version 313 \ # --only-binary=:all: --platform manylinux_2_28_x86_64 -d ./wheels_offline # Copiar los .whl al servidor en /opt/librerias, luego instalar SIN internet: pip install --no-index --find-links=/opt/librerias pandas numpy

Paso 3 — Ejecutar la prueba

python -c "import pandas as pd; import numpy as np; df = pd.DataFrame(np.random.randn(100000, 2)); df.info(); print(f'\nPROMEDIO: {df[0].mean():.4f} | PYTHON 3.13.5 LISTO')"

Paso 4 — Limpiar y salir del venv

# Si instaló pandas/numpy solo para la prueba y no son del proyecto, quítelos: pip uninstall -y pandas numpy deactivate
El ETL gestiona sus dependencias reales desde requirements.txt durante el despliegue (Manual 5). Esta prueba solo confirma que el Python compilado funciona con librerías nativas dentro del venv. Si pandas/numpy ya son parte del proyecto, no los desinstale: solo ejecute deactivate.

VIII. Solución de Problemas Comunes

DescripciónSolución
module 'ssl' has no attribute '_SSL_METHOD'Verificar que openssl-devel estaba instalado ANTES de compilar. Recompilar con --with-openssl=/usr.
ctypes.util.find_library returned NoneAplicar la corrección libffi del paso 4.2. Verificar: ldconfig -p | grep ffi.
PyInstaller falla con Python library is not sharedConfirmar Py_ENABLE_SHARED=1 (prueba 5.1). Ejecutar ldd $(which python3.13).
ImportError: libpython3.13.so no se encuentraEjecutar sudo ldconfig. Verificar que /etc/ld.so.conf.d/python313.conf existe con la ruta correcta.
oracledb thick mode falla con DPI-1047 (libclntsh.so no encontrado)Registrar la ruta del Oracle Client en ldconfig: echo "/opt/oracle/client_home/lib" | sudo tee /etc/ld.so.conf.d/oracle-client.conf · sudo ldconfig. Verificar: ldconfig -p | grep libclntsh. Si persiste, confirmar permisos o+rX sobre client_home/lib. No depende de oinstall.
