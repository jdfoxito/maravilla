✅ Atajo. Este manual es el último de la serie: el bloque siguiente comprueba de una sola vez que los Manuales 1–4 se cumplieron. Ejecútelo como python. Si TODAS las líneas imprimen [OK], el servidor está listo: continúe con la sección II (Dev/Test) o III (Producción) según su ambiente. Cada [FALTA] indica el manual al que volver.

II. Flujo DESARROLLO y TEST — Ejecución del Instalador

📍 Aplica a Desarrollo y Test (NO a Producción). Aquí se compila: se descarga la solución del repositorio, se compila y se genera el ejecutable con PyInstaller. En Producción no se hace esto (ver sección III).
⏭️ Si está desplegando en Producción (10.2.2.218), salte toda esta sección y vaya directo a la III. En producción no se compila ni se ejecuta el instalador.

2.1 Preparación del script

cd /home/python/sri_datos_abiertos_facturacion/config/ sed -i 's/\r$//' datos_abiertos.bash # quitar saltos de línea Windows (CRLF) chmod +x datos_abiertos.bash

2.2 Ejecución (usuario python, con sudo)

sudo ./datos_abiertos.bash

2.3 Flujo del script

El instalador realiza automáticamente:

  • Verificación de Python 3.13.5 (SSL, ctypes, Py_ENABLE_SHARED).
  • Verificación de Java 21.
  • Verificación de cliente Oracle y wallet (STAR_BI_DWH y SRIDW).
  • Verificación de Spark 4.0.2 y del servicio sri-datos-abiertos-spark (instalado en el Manual 1).
  • Verificación de conectividad SSH a los servidores de descarga.
  • Creación de la estructura de directorios.
  • Verificación de archivos de configuración (configlnx.toml y requirements.txt).
  • Recreación limpia del entorno virtual Python (venv).
  • Instalación de dependencias + PyInstaller.
  • Generación de scripts de prueba y del ejecutable con PyInstaller.
El ejecutable se genera en .../dist/. El log detallado queda en .../logs/instalador_YYYYMMDD_HHMMSS.log.

2.4 Instalación offline de dependencias (servidores sin internet)

⏭️ Solo si el servidor NO tiene internet. Si el pip install del instalador (2.2) terminó sin error, las dependencias ya están y puede saltar a la sección IV. Use esta sección únicamente si el instalador falló al instalar dependencias por falta de internet.
# En una máquina CON internet, descargar los wheels para Python 3.13 / Linux x86_64: pip download -r requirements.txt --python-version 313 --only-binary=:all: \ --platform manylinux_2_28_x86_64 -d ./wheels_offline # Copiar los .whl al servidor en /opt/librerias, luego instalar dentro del venv: cd /home/python/sri_datos_abiertos_facturacion source venv/bin/activate pip install --no-index --find-links=/opt/librerias -r requirements.txt pip list deactivate

IV. Validación Post-Instalación

⚠️ Antes de ejecutar la aplicación, las tres validaciones siguientes deben pasar: Python con sus características especiales (ctypes), wallet de ambas bases y servicio Spark arrancado.
⏭️ Si el bloque 0 del inicio dio todo [OK], los puntos 4.1–4.3 ya están cubiertos a alto nivel; ejecútelos solo si quiere la verificación detallada o si va a correr los scripts de prueba (4.4).

4.1 Verificar Python y sus características especiales (ctypes / shared)

source /home/python/sri_datos_abiertos_facturacion/venv/bin/activate python -c "import ssl; print('SSL OK')" python -c "import _ctypes; print('ctypes OK')" python -c "import ctypes; ctypes.CDLL('libclntsh.so'); print('Oracle Client (ctypes) OK')" python -c "import sysconfig; print('shared =', sysconfig.get_config_var('Py_ENABLE_SHARED'))" # shared = 1

4.2 Verificar el wallet (ambas bases) desde Python

python3 - << 'PYEOF' import oracledb, os os.environ['TNS_ADMIN'] = '/opt/oracle/client_home/network/admin' os.environ['ORACLE_HOME'] = '/opt/oracle/client_home' oracledb.init_oracle_client() for alias in ('STAR_BI_DWH', 'SRIDW'): with oracledb.connect(dsn=alias) as con, con.cursor() as cur: cur.execute("SELECT 1 FROM dual") print(f"OK {alias}:", cur.fetchone()) PYEOF deactivate

4.3 Verificar que el servicio Spark está arrancado

sudo systemctl status sri-datos-abiertos-spark --no-pager # Esperado: active (running) # Puerto Spark Connect timeout 2 bash -c "echo >/dev/tcp/localhost/15002" && echo "PUERTO 15002 OK" # Si no está activo, arrancarlo (su instalación está en el Manual 1): sudo systemctl start sri-datos-abiertos-spark sudo journalctl -u sri-datos-abiertos-spark -n 50 --no-pager

4.4 Pruebas funcionales con los scripts del proyecto

source /home/python/sri_datos_abiertos_facturacion/venv/bin/activate # Prueba de Oracle Wallet: python /home/python/sri_datos_abiertos_facturacion/tests/test-wallet.py # Prueba de Spark + Oracle (usa el servicio en localhost:15002): python /home/python/sri_datos_abiertos_facturacion/tests/test-spark-wallet.py deactivate

4.5 Ejecutar la aplicación

/home/python/sri_datos_abiertos_facturacion/dist/datos_abiertos1_0 # o el binario copiado en producción: # /home/python/sri_datos_abiertos_facturacion/datos_abiertos1_0
Una vez validada la ejecución, calendarizar con cron según la operación (p.ej. diaria). El envío de correo de notificación se valida en el Manual 1 (sección IX) y se configura en configlnx.toml.
