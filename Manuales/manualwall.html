0. Usuario de Ejecución del Manual (LEER ANTES DE EMPEZAR)

REGLA GENERAL: Todo este manual se ejecuta con el usuario local python. No se utiliza el usuario root de forma directa ni el usuario oracle. Los comandos que requieren privilegios de administrador están prefijados con sudo y los ejecuta el mismo usuario python, que debe pertenecer al grupo wheel.

0.1 Conexión al servidor y cambio al usuario python

Paso 1 — Conéctese al servidor con su usuario institucional vía SSH:

ssh <su_usuario>@10.2.2.218

Paso 2 — Cámbiese al usuario python:

sudo su - python

# Alternativa si conoce la contraseña del usuario: su - python

Paso 3 — Confirme la sesión activa:

whoami
# Esperado: python

echo $HOME
# Esperado: /home/python

0.2 Verificación de la configuración del usuario python (prerequisito obligatorio)

Antes de ejecutar cualquier sección del manual, verifique que el usuario python cumple con la configuración definida en el documento de requerimientos de infraestructura del proyecto (sección 1.2 Usuario del proyecto):

id python
# Esperado: el listado de grupos debe incluir wheel (sudo) y oinstall (Oracle)
# Ejemplo: uid=1000(python) gid=1000(python) groups=1000(python),10(wheel),54321(oinstall)

sudo -l
# Esperado: el usuario python debe poder ejecutar comandos con sudo
# Referencia en Desarrollo (sritrazadesa): (ALL) NOPASSWD: ALL
SI LA VERIFICACIÓN FALLA (el usuario python no existe, no pertenece a wheel, no puede ejecutar sudo, o no existe el grupo oinstall): DETENGA la ejecución del manual y solicite a Infraestructura/Operaciones la configuración del usuario mediante requerimiento formal. Utilice la plantilla del Anexo B de este documento. La creación del usuario es responsabilidad del aprovisionamiento del servidor y no forma parte de este manual.
NOTA: En manuales anteriores (RHEL 8) la instalación del cliente Oracle se realizaba con un usuario oracle dedicado y grupo dba. En el esquema actual del proyecto Trazabilidad Fiscal ese usuario no se utiliza: el cliente Oracle, los wallets y la configuración de red son propiedad del usuario python (grupo oinstall), y la instalación se realiza íntegramente con python + sudo.

I. Prerrequisitos

1.1 Verificación de Oracle Client 21c instalado

IMPORTANTE: Antes de continuar, verifique que Oracle Client 21c esté presente en el servidor. Si no está instalado, proceda con el Anexo A. Este manual es exclusivo para Oracle 21c Client Home, no el Instant Client.

No se usa Instant Client 21c (instantclient-tools-linux.x64-21.x) porque NO incluye orapki, mkstore ni tnsping. Se debe usar el Oracle Client Home 21c completo.

Luego de instalar el Anexo A, en caso de haber requerido instalar, continuar con el manual.

Paso 1 — Verificar existencia del directorio ORACLE_HOME

ls -ld /opt/oracle/client_home

Esperado: drwxr-xr-x ... /opt/oracle/client_home

Si no existe: Contacte al DBA para instalar Oracle Client 21c Home o proceda con la instalación manual (ver Anexo A).

Paso 2 — Verificar librerías críticas del cliente Oracle

ls -la ${ORACLE_HOME}/lib/libclntsh.so.21.1 2>/dev/null || echo "FALTA: libclntsh.so.21.1"
ls -la ${ORACLE_HOME}/lib/libnnz21.so 2>/dev/null || echo "FALTA: libnnz21.so"
which sqlplus 2>/dev/null || echo "FALTA: sqlplus en PATH"

Esperado: Todos los archivos deben existir. Si falta alguno, reinstale el Oracle Client 21c.

La versión debe salir el 21c para el cliente; según la versión que esté instalando, en este manual se utilizó la versión 21.3:

[python@sritrazadesa ~]$ sqlplus -v

SQL*Plus: Release 21.0.0.0.0 - Production
Version 21.15.0.0.0

Paso 3 — Verificar herramientas de wallet (orapki, mkstore, tnsping)

which orapki 2>/dev/null || echo "FALTA: orapki"
which mkstore 2>/dev/null || echo "FALTA: mkstore"
which tnsping 2>/dev/null || echo "FALTA: tnsping"

Esperado: Rutas como /opt/oracle/client_home/bin/orapki

Si faltan: Asegúrese de que ${ORACLE_HOME}/bin esté en el PATH del usuario python. Si usó Instant Client 21c, reinstale con Client Home 21c completo (ver Anexo A).

1.2 Configuración de variables del ambiente respectivo (si no están definidas)

Si las variables ORACLE_HOME, ORACLE_WALLET_PATH o TNS_ADMIN no están definidas, configúrelas de forma persistente para el usuario python.

Paso 1 — Verificar variables actuales

echo $ORACLE_HOME
# Debe mostrar: /opt/oracle/client_home

echo $ORACLE_WALLET_PATH
# Debe mostrar: /opt/oracle/wallets

echo $TNS_ADMIN
# Debe mostrar: /opt/oracle/client_home/network/admin

echo $LD_LIBRARY_PATH | grep oracle
# Debe contener: /opt/oracle/client_home/lib

Resultado en el ambiente respectivo, por ejemplo en desarrollo (sritrazadesa.sri.ad):

[python@sritrazadesa ~]$ echo $TNS_ADMIN
/opt/oracle/client_home/network/admin
[python@sritrazadesa ~]$ echo $ORACLE_HOME
/opt/oracle/client_home

Paso 2 — Exportar variables (sesión actual)

export ORACLE_HOME=/opt/oracle/client_home
export ORACLE_WALLET_PATH=/opt/oracle/wallets
export TNS_ADMIN="${ORACLE_HOME}/network/admin"
export LD_LIBRARY_PATH="${ORACLE_HOME}/lib:${LD_LIBRARY_PATH}"
export PATH="${ORACLE_HOME}/bin:${PATH}"

Paso 3 — Hacer persistente en ~/.bashrc (usuario python)

cat << 'EOF' >> /home/python/.bashrc
# === Oracle Client 21c --- Trazabilidad Fiscal ===
export ORACLE_HOME=/opt/oracle/client_home
export ORACLE_WALLET_PATH=/opt/oracle/wallets
export TNS_ADMIN="${ORACLE_HOME}/network/admin"
export LD_LIBRARY_PATH="${ORACLE_HOME}/lib:${LD_LIBRARY_PATH}"
export PATH="${ORACLE_HOME}/bin:${PATH}"
# ================================================
EOF

# Recargar perfil:
source /home/python/.bashrc

1.3 Permisos del directorio de wallets

ls -la /opt/oracle/wallets 2>/dev/null || echo "Directorio no existe, se creará en paso III"

# Permisos recomendados: drwxr-x--- python:oinstall

En servidores nuevos aprovisionados según este manual, la propiedad es python:oinstall (ver Anexo A.3) y esta observación no aplica.

II. Configuración de TNSNAMES.ORA y SQLNET.ORA

2.1 Crear/editar sqlnet.ora (obligatorio para wallet)

El archivo sqlnet.ora le indica a Oracle Client dónde buscar el wallet. Sin este archivo, la autenticación por wallet fallará con ORA-12638.

Paso 1 — Crear/Editar sqlnet.ora

vim ${TNS_ADMIN}/sqlnet.ora

Contenido mínimo requerido (validado en desarrollo):

# sqlnet.ora Network Configuration File:
# /opt/oracle/client_home/network/admin/sqlnet.ora
# Generated by Oracle configuration tools.

NAMES.DIRECTORY_PATH= (TNSNAMES, EZCONNECT)
SQLNET.AUTHENTICATION_SERVICES= (NTS)

WALLET_LOCATION =
  (SOURCE =
    (METHOD = FILE)
    (METHOD_DATA = (DIRECTORY = /opt/oracle/wallets))
  )

SQLNET.WALLET_OVERRIDE = TRUE
SSL_CLIENT_AUTHENTICATION = FALSE
SSL_VERSION = 0

Notas del archivo real en el ambiente:

  • WALLET_LOCATION apunta exactamente a /opt/oracle/wallets
  • SQLNET.WALLET_OVERRIDE = TRUE fuerza el uso del wallet sobre otras autenticaciones
  • SSL_VERSION = 0 habilita negociación automática (validado funcional en 21c)

III. Creación de Wallet con ORAPKI (Oracle 21c Client Home)

En Oracle 21c sobre RHEL 10.1 se utiliza orapki para crear el wallet con autologin, seguido de mkstore para agregar credenciales.

3.1 Crear directorio del wallet

sudo mkdir -p /opt/oracle/wallets
sudo chown python:oinstall /opt/oracle/wallets
sudo chmod 750 /opt/oracle/wallets

# Se ejecuta con el usuario python utilizando sudo (la ruta /opt requiere privilegios).

3.2 Crear wallet con autologin

Se deberá en primera instancia usar los wallets creados en el servidor sriapp36; en caso de poder conseguirlos, proceder a ubicarlos en /opt/oracle/wallets y hacer las validaciones respectivas; de lo contrario, proceda con el Paso 1 de este inciso:

mkstore -wrl /opt/oracle/wallets -listCredential

En el password que le solicita, colocar el password del Ambiente del servidor sriapp36 para el Wallet. Si se listan las credenciales, deberá verse la credencial STAR_BI_DWH y procedemos a intentar conectarnos:

sqlplus /@STAR_BI_DWH
Deberá mostrarse de la siguiente manera en el caso de la conexión exitosa; si es así se omitirán los Pasos 1 y 2 de este inciso y los puntos 3.3, 3.4, 3.5 y 4.1 de este manual. 
SQL*Plus: Release 21.0.0.0.0 - Production on Thu May 28 08:56:15 2026
Version 21.15.0.0.0
Copyright (c) 1982, 2019, Oracle. All rights reserved.

Last Successful login time: Thu May 28 2026 08:16:18 -05:00

Connected to:
Oracle Database 19c Enterprise Edition Release 21.0.0.0.0 - Production
Version 19.29.0.0.0

SQL>

Si no se conecta y le pide password, o presenta algún tipo de error en el listado de las credenciales o en el intento de conexión vía wallet con sqlplus, entonces continuar con los Pasos del manual a continuación:

Paso 1 — Crear wallet vacío

orapki wallet create -wallet /opt/oracle/wallets

El sistema solicitará una contraseña para el wallet. Anótela en un gestor de contraseñas seguro.

# Password solicitado: [Ingrese contraseña del wallet]
# Ejemplo: WalletPass123 (CAMBIAR SEGÚN POLÍTICA DE SEGURIDAD)

Paso 2 — Habilitar auto_login

orapki wallet create -wallet /opt/oracle/wallets -auto_login

Esto genera el archivo cwallet.sso que permite la autenticación sin solicitar contraseña en runtime.

3.3 Verificar archivos del wallet

ls -la /opt/oracle/wallets/
# Esperado:
# -rw------- 1 python oinstall cwallet.sso  (wallet con autologin)
# -rw------- 1 python oinstall ewallet.p12  (wallet maestro)

3.4 Agregar credenciales al wallet

Paso 1 — Crear credencial para el TNS_ALIAS

mkstore -wrl /opt/oracle/wallets -createCredential STAR_BI_DWH [ESQUEMA] [CLAVE_ORACLE]

Donde:

  • [ESQUEMA]: Usuario de base de datos (ej: BI_DWH, CATASTRO, FACTURACION)
  • [CLAVE_ORACLE]: Contraseña del esquema (ingresada por DBA autorizado)
# Ejemplo concreto (adaptar según ambiente):
mkstore -wrl /opt/oracle/wallets -createCredential STAR_BI_DWH BI_DWH BI_DWH
# Password del wallet solicitado: [PASSWORD SEGÚN POLÍTICA DE SEGURIDAD]
# Password del esquema Oracle solicitado: [Clave del usuario BI_DWH]
Seguridad: Las contraseñas del wallet y del esquema Oracle debe proporcionarlas su DBA según el ambiente.

3.5 Verificar credenciales almacenadas

mkstore -wrl /opt/oracle/wallets -listCredential
# Salida esperada:
# Credential alias: STAR_BI_DWH
# Credential username: BI_DWH

Paso 2 — Crear script de prueba testwallet.py

Asegurarse que el directorio donde va a ejecutar tenga los permisos, por ejemplo, en el directorio /datos/oracle/tests:

cat << 'PYEOF' > /home/python/sri_trazabilidad_fiscal/tests/testwallet.py
import oracledb
import os

os.environ['TNS_ADMIN'] = '/opt/oracle/client_home/network/admin'
os.environ['ORACLE_HOME'] = '/opt/oracle/client_home'

try:
    oracledb.init_oracle_client()
    pool = oracledb.create_pool(
        dsn='STAR_BI_DWH',
        min=2,
        max=10,
        increment=2,
        getmode=oracledb.POOL_GETMODE_WAIT,
        wait_timeout=30,
        timeout=30,
        max_lifetime_session=1800,
        ping_interval=60,
        externalauth=True,
        homogeneous=False,
    )
    with pool.acquire() as connection:
        with connection.cursor() as cursor:
            cursor.execute("SELECT COUNT(1) + 145 FROM BI_DWH.BDW_TRAZABILIDAD_CABECERA_INFO ")
            result = cursor.fetchone()
            print("Resultado:", result)
except oracledb.DatabaseError as e:
    error, = e.args
    print("Error Oracle:", error.message)
except Exception as e:
    print("Error general:", str(e))
print("ENDLE")
PYEOF

V. Configuración en tf.toml (CRÍTICO)

5.1 El archivo de configuración del proyecto DEBE contener

# tf.toml
[oracle]
wallet = "STAR_BI_DWH"
# Nota: La contraseña NO va aquí, se obtiene del wallet
# IP Producción: 10.2.2.218 | Desarrollo: 10.12.4.94 | Preproducción: 10.12.5.204

5.2 Validación automática por el script bash

El instalador trazabilidad_fiscal.bash verifica:

  • Existencia de tf.toml
  • Que jdbc_url contenga formato "jdbc:oracle:thick:@<TNS_ALIAS>"
  • Que el TNS_ALIAS exista en tnsnames.ora
  • Que el wallet tenga credencial para ese TNS_ALIAS

Anexo A. Instalación de Oracle Client 21c (Client Home, image-based)

⚠️ NO usar Instant Client 21c — no incluye orapki, mkstore, tnsping.
Se debe usar el Oracle Client Home 21c completo: LINUX.X64_213000_client_home.zip (~923 MB).
Requiere cuenta Oracle + aceptar licencia.
Solo ejecutar si el paso I.1 falló. Se ejecuta con el usuario python utilizando sudo para los comandos sobre /opt (no se utiliza root directamente; el usuario python debe pertenecer al grupo wheel — ver sección 0). Se recomienda Oracle 21.3c.

A.1 Descargar Oracle Client 21c Home desde el portal de Oracle

Debe copiar de la carpeta compartida el instalador LINUX.X64_213000_client_home.zip hacia el servidor, en la ruta donde vaya a realizar la instalación, por ejemplo: /opt/oracle

O en caso contrario utilizar la siguiente opción:

Acceder a Oracle Database 21c Download for Linux x86-64 con cuenta Oracle válida, aceptar licencia, y descargar:

LINUX.X64_213000_client_home.zip

A.2 Descomprimir y estructurar

cd /opt
sudo mkdir -p oracle
cd oracle
sudo unzip -q LINUX.X64_213000_client_home.zip -d client_home

# Verificar estructura Client Home (debe tener /bin y /lib)
ls /opt/oracle/client_home/bin/sqlplus
ls /opt/oracle/client_home/bin/orapki
ls /opt/oracle/client_home/bin/mkstore
ls /opt/oracle/client_home/bin/tnsping
# Resultado esperado: los 4 archivos existen (Client Home sí los trae)

A.3 Crear directorios de red y asignar permisos

sudo mkdir -p /opt/oracle/client_home/network/admin
sudo mkdir -p /opt/oracle/wallets
sudo chown -R python:oinstall /opt/oracle
sudo chmod 750 /opt/oracle/wallets
